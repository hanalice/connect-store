## 窗口外新发现（抽验伴随捕获，不在原 6 点内）

### N1. AI 导购感知不到手动加购行 / 无法清空购物车

- **现象**：目录页手动加购 1 条裙子，对话中加 1 个包包，说「清空购物车」
  ——助手做不到，且对购物车里已有的手动加购行完全不可见。
- **根因（代码实证）**：购物车是**纯客户端** zustand persist store
  （`src/features/cart/store/useCartStore.ts`，localStorage 键 `clo-cart`），
  BFF/模型侧没有任何购物车状态；server 工具集只有 4 个
  （`server/tools/`：addToCart / getProductDetails / placeOrder / searchCatalog），
  **无读购物车工具、无清空工具**；addToCart 本身也只是回执语义
  （`server/tools/addToCart.ts:1-4` 边界注释：不写购物车状态落点）。
  即：AI 对它自己没有经手加购的购物车内容零可见，是架构边界而非缺陷。
- **待澄清（产品语义）**：混合购物车（手动 + AI 加购）下，AI 该不该看得见、
  该不该能清？澄清结论决定 F-1 方案选型。
- **设计澄清（2026-10-28 用户拍板方向）**：不让模型读购物车**不是安全设计**，
  是架构缝隙（购物车纯客户端态、模型在服务端，G2.1 边界即声明 addToCart
  只回执、不落状态）。用户给出新方向：**目录页撤掉「加入购物车」按钮、
  购物车降级为只读效果视图、AI 是唯一写者、人是审批者**——人工改量本就不
  支持（改了会话会出错），混合写者是既无必要又有害的口子。
- **Story（single-writer cart + human approver）**：
  1. **一致性**：H2 走查真实踩过 dialog↔cart 在 edit 路径上的不一致
     （G3.3c 修复的正是这类 bug）。人 + AI 双写者需要并发合并/对齐机制，
     对 demo 规模是 over-engineering；关闭人工写路径 = 用架构消除整类
     一致性问题（single-writer 原则），N1 可见性缺口恰好反证混合写者下
     AI 无法对「它没经手的商品」负责——审批卡审计语义因此不完备。
  2. **HITL 收口**：资金动作全收敛到审批卡单点审计；审批范围 =
     AI 全程经手的商品集合，语义完备。
  3. **降级路径定位**：目录页是 AI 不可用时的浏览兜底，降级路径宁可
     少做不可做错（fail-safe 只读）。
  4. **行业锚点**：agentic commerce 主流（Amazon Rufus / Klarna assistant /
     OpenAI Instant Checkout）正是「代理持有交易主导权、人只做确认」——
     撤人工加购入口是行业方向一致的主动取舍，不是 demo 偷懒。
  5. **诚实边界**：全功能 parity（人工改量/删除 + 并发合并）列为 roadmap，
     当前工程预算全投 AI 闭环。
  6. **「去结算（即将上线）」占位按钮 = story 引子**（2026-10-28 用户拍板
     维持现状）：drawer 页脚永禁用按钮保留视觉完整性；其「即将上线」的真实
     含义 = 传统人工结算不建设，结算已由「对 AI 说下单 → 审批卡」整体替代——
     演示时正好用作 agentic commerce 叙事切入点。

- **诊断结论（2026-10-28 复测）**：全站零朗读确为**环境问题**（复测可正常朗读，

  目录页 `ProductCard.tsx:149` 卡片 aria-label（title by creator, price…）、
  `SearchBar.tsx:68` aria-label；助手页对话流复用同一 ProductCard

  composer `ChatPanel.tsx:259` aria-label、消息区 `:127-128` role="log"。

### N2a. 非截断的 title/creator 不可聚焦，讲述人 Tab 序列读不到

- **现象**：title/creator 长度未截断的卡片，触发元素连焦点都没有，
  讲述人在 Tab/焦点路径下读不到这两个视觉文本；用户预期=讲述人可读全部视觉元素。
- **根因（有意设计，d4f1229）**：tabindex 只在截断时挂
  （`ProductCard.tsx:53-58`——截断才挂 tabindex、才有 tooltip 触发行为；
  未截断卡片无触发行为）。
- **口径澄清（焦点 ≠ 朗读）**：
  - **扫描/浏览模式**（讲述人箭头导航）：文本节点天然可朗读，且卡片级
    aria-label 已把 title/creator/price 打包为整卡可访问名——该路径下
    「所有视觉元素可读」**已成立**。
  - **焦点/Tab 模式**：tabindex 只给截断触发器是刻意的「卡即单元」信息
    架构——若 title/creator 始终可聚焦，每卡 Tab 序列 +2 停留点，键盘
    效率下降；信息已由卡级 aria-label 承载。
- **拍板 + 修复（2026-10-28，已施工）**：聚焦设计维持现状（截断才挂 tabindex），
  把「加入购物车」按钮 accessible name 从「加入购物车，{title}」补全为
  「加入购物车，{title}，{creator}，{price}」（`CatalogProductCard.tsx`；
  价格口径与卡片 aria-label 一致：PAID `$X.XX` / 其余 PRICING_LABEL）。
  依据：读屏用户 Tab 路径下唯一可聚焦决策点就是按钮，name 必须自含
  title/creator/价格三要素。同步：单测 3 处、E2E-AI-18 两处按 name 定位、
  `docs/test_cases.md` E2E-AI-18 描述、组件头注释。
- ~~待拍板：维持现状 vs title/creator 始终 tabindex=0~~（已由上条取代：
  维持聚焦现状 + 按钮名补全，title/creator 不加 tabindex）。
- **二次拍板 + 修复（2026-10-28，G5.1 后）**：G5.1 撤掉加购按钮后，非截断卡片
  在 Tab/焦点路径下完全消失（讲述人扫描模式仍可读，焦点模式真缺口）——
  改判**卡片整体进 Tab 序**：`<article tabIndex=0>`（`ProductCard.tsx`），
  aria-label 自含 title/creator/price 即焦点路径内容通道；补
  `.card:focus-visible` 焦点环；截断 title/creator 仍各自作 tooltip 触发器
  （嵌套焦点，不冲突）。锁定测试同步改判（原「无卡级停留点」断言翻转为
  `tabindex="0"` + Tab 序 Before→卡→After）。用户原话方案存档：卡片聚焦承载
  整体信息；按钮若复归，按钮名只需 title+动作。
