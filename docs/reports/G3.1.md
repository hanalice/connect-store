## 四、通用资产沉淀

> 摘要写这里，详情追加与否由 PM 在第六节裁决（挂 G4.3 文档批次）。

- **ai SDK v7 帧协议事实（高价值）**：`tool-output-available` 帧无 `toolName`，工具名只能
  从 `tool-input-available` 帧登记处经 `toolCallId` 反查——G3.2/G3.3 新工具接线照搬
  `useAssistantStore.ts:167-191` 的查表模式。
- **Zustand persist 落地惯例（裁决③，高价值）**：键名 `clo-` 前缀（`clo-cart`）+
  `partialize` 只 persist 业务态（items）、UI 态排除；测试隔离 = `beforeEach` 清
  localStorage + `setState` 重置，恢复实证 = 读 `localStorage` 断言 partialize 形态 +
  `persist.rehydrate()`（`useCartStore.test.ts:94-119`）。
- **badge/drawer 双通道触发 + 形态锁定单测法（中价值）**：加购回执自动打开 + badge 点击
  toggle；「0 值也显示」的锁定形态用 accessible name 断言（`getByRole('button', {
name: '购物车，0 件商品' })`），比视觉断言稳。
- CartConfirmCard / uiRegistry 新 key 沿用 G2.4 白名单骨架（业务 error 先分流 → zod
  schema → 渲染；决策函数纯渲染零副作用），零新增模式成本。

## 五、风险与遗留

- **persist 内嵌商品快照**：`CartItem` 挂完整 Product（裁决⑥ 拍板），刷新后 cart 展示的是
  加购时刻快照——catalog 侧价格/标题后续变更不回溯已持久化条目。**预警 G3.2**：下单计价
  必须以 server 侧实时数据为准重新校验，不得信任前端快照。
- **drawer 每次加购回执都自动打开**，即使用户刚手动关闭（裁决⑤ 触发① 的字面落地）。
  按工单锁定为本 G 形态；若后续 UX 反馈骚扰，需 PM 显式裁决调整，coder 不得自改。
- **regression-index §1 快速回归命令表「覆盖」列过时**（「vitest 7 文件 / 49 用例」
  「E2E-AI-01~08」「~7s」，自 G2.3 起未随用例数更新，现为 18 文件 / 92 用例 /
  E2E-AI-01~17 / ~14s）——文档欠账，挂 G4.3 批次顺改。
- badge/drawer/确认卡等组件级单测（5 条）与接线用例（4 条）沿用 G2.4 惯例不单独编号
  （编号已覆盖 UT-CART-01~03 / E2E-AI-16~17），G4.1 测试矩阵收口时如需再统一。
- E2E-AI-09 仍 ⬜（归 G4.1，本 G 未重跑未改）；无其他高危遗留。
