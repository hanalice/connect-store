### 7. prompt 约束独立评估（QA 硬指标 5）

`server/chat-prompt.ts:24` 原文：

> 当用户消息以「订单修改重发」开头并给出明确商品清单与数量时，严格按清单调用
> placeOrder 提交（会再次进入审批），不要反问、不要增减数量；普通闲聊中提到商品名
> 或数字不构成下单意图。

**裁断：成立。** 理由：① 触发条件是「以固定标记开头」——闲聊提到商品名/数字不满足
前缀条件，且同句后半显式声明其不构成下单意图，双向往均堵住；② 该约束只**收窄**了
存量「明确要求下单/结算时调用 placeOrder」的触发面，未扩大下单意图；③ 即便用户
手工键入标记，仍要过 zod input schema + 二次审批卡人工复核（四护栏其余三护栏存量），
风险有兜底。`server/chat-prompt.test.ts` 3 用例亲测全绿（触发句在位 / 防误触发半句
在位 / 存量审批约束零弱化）。
