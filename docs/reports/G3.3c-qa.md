## 三、缺陷清单

### Q-D-01（major，初验阻断 → 复验关闭）：alignWithOrderItems 删行范围过达——静默删除订单外用户条目

**现象（初验）**：`useCartStore.ts` alignWithOrderItems 对**所有**不在 edit 后 draft 里的
cart 行一律删行（`orderQty === undefined → return []`），包括用户手动加购、与订单无关的
商品。施工按工单裁决①字面实现并将该用例锁进测试（UT-CART-04 断言 productFree/
productViewOnly 被删；assistant edit 同步用例断言 CART_PRODUCT 被删）。

**裁断（初验）：打回（判为过达），要求 PM 修订裁决①**。理由：

1. **文本依据支持窄读**：裁决①原文「cart 有而订单**不再含**的条目 → 删行」——「不再含」
   隐含「原先含有」前提；从未入单的行无所谓「不再含」。窄读 = 只对「原订单含有的
   productId」（含 edit 移除的条目）做对齐删除，订单外条目保留。
2. **同 G 自洽性**：本 G 裁决②对同类行（订单不含的 cart 行）明确「跳过不补、只扣不补」。
   初验实现造成同状态路径依赖的分裂结果：cart {A(订单内), B(用户手动)}——用户点 approve
   → deduct 保留 B；用户先 edit 订单 → align 删除 B。同一 cart/订单状态因 UI 路径不同
   而 B 存 / B 亡，两触点哲学相反。
3. **真实用户旅程**：cart 是本应用主购物面（G3.1 加购回执自动开 drawer、目录页手动加购
   为常态）。await_human（订单待审）期间用户加购下一单意向商品 B 属高概率行为；随后
   edit 待审订单，B 无提示消失、不可撤销 = 静默的用户数据丢失，超出 H2 缺陷动机
   （「订单所含条目」的 cart 漂移修复）。
4. **返工面小**：editOrder 内可取原订单 `approval.items` 做 productId 白名单；
   需同步改 alignWithOrderItems 实现 + UT-CART-04 + assistant edit 同步用例
   （三处均断言了订单外行被删）。

**PM 处置（2026-10-27，签核裁决）**：**同意 QA 窄读主张，裁决①已修订**（工单
G3.3c.md 裁决①原文已由 PM 直改，打回第 1 轮/上限 2）：作用域 = 被 edit 卡的原订单
items；draft 含 → 数量直写对齐；原订单含而 draft 不含 → 删行；**订单外 cart 行一律
保留**；数量对齐不分来源（cart 无来源元数据，不引 provenance）。返工面 = coder
改 `alignWithOrderItems` 实现（+scope 参数）与 editOrder 调用点（传 `approval.items`）

- 同步改 UT-CART-04 与 assistant edit 同步用例（订单外行保留断言）+ 根单测重跑。
  **观察项裁定：O-1（deduct 幂等守卫）与 O-2（空数组守卫）均不加**——现实约束已
  挡（帧单轮单次投递 / 调用侧 items 空提前 return），与既有「参数不做防御」风格一致；

**QA 复验：关闭（2026-10-27）**。复验证据：① 两参签名落地（useCartStore.ts:80
`alignWithOrderItems(orderItems, draftItems)`），scope 收窄实现 = 订单外行 `return [item]`
保留、scope 内 draft 不含删行、draft 含直写对齐、无新增分支；② editOrder 调用点
（useAssistantStore.ts:625）传 `approval.items`（被 edit 卡原订单）+ draft `items`，
时机仍在 superseded 投影同处；③ 双断言回归锁齐位——UT-CART-04 断言 productViewOnly

## 四、风险与遗留

- **O-1（低风险观察，PM 裁定不加守卫）**：deductExecutedItems 无幂等守卫——同一
  toolCallId 的重复输出帧会二次扣减。现实约束：帧每轮执行只投递一次；刷新后回放无审批
  记录走跳过分支。PM 裁定：不加「已扣 toolCallId 集合」防御。
- **O-2（低风险观察，PM 裁定不加守卫）**：alignWithOrderItems 空数组入参会删光全部
  cart 行；action 层无守卫，但唯一调用侧 editOrder 已有 `items.length === 0` 提前 return
  挡住。PM 裁定：维持与既有 add/remove/clear 一致的「参数不做防御」风格。
- **O-3（基线注记漂移，PM 已知悉）**：工单「现状」注 server 75，实测 HEAD 为 76——
  +1 来自已提交的 b8fddc7（H2 热修），本 G server diff 为零，不构成越界；PM 裁定基线句
  以 server 76 为准。
- **遗留**：无阻断遗留。H2 人工走查（edit 后抽屉对齐 / 执行后扣减可感）仍为本 G 的终端
  证明，待走查执行（不受复验影响——返工只收窄删行范围，触点位置与时机未动）。
