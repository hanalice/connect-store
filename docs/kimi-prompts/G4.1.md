## 裁决②：端口敏感性（G3.4 §二⑦ 升级项，CI 前置）

- 临时/非标准端口（18787/5199 式 harness）对 5 个 mid-stream 观测类用例确定性
  flake（HEAD 同复现，与施工无关）。G4.1 双路径裁决：
  - **优先**：定位根因并修复（探针线索：curl 经代理 SSE 逐帧正常，疑 dev-server
    环境时序敏感）；修复须标准端口三连跑 + 临时端口复跑双绿；
  - **兜底（可接受结论）**：根因不可修则给出「E2E 门禁绑定标准端口 8787/5173 +
    Playwright webServer 自拉（`reuseExistingServer: false` 已如此），CI 复用同配置」
    的不可动结论，并在 ubuntu-latest 上实测标准端口三连跑稳定后，E2E mock **方可**
    入 CI；结论写进报告 §三。
- **E2E 入 CI 是目标不是硬指标**：若兜底路径成立且 CI 实测稳定 → E2E 入 CI；若 CI
  环境仍 flake → CI 暂不含 E2E（明示结论，E2E 留本地门禁），不阻塞本 G 签核。

## 裁决③：E2E-AI-09 容错改造（挂账授权改造既有用例）

- 改造点 = `:37` 硬断言 `finalText.length > firstText.length`（上游单帧短回复 + 无
  reasoning 时首采即全文 → 等长误伤）。容错口径：**增长步数 ≥1 即通过**（首采即
  全文视为合法短回复），保留「输入恢复 + 无 alert 横幅」两条硬断言不变。
- 本改造是**登记过的挂账任务**（G2.3 签核起挂 G4.1），工单显式授权，不属于「弱化
  既有用例」红线；流式健康度仍由 mock 门禁 23 条覆盖。
- 验收须附**带 BFF 的 live 复跑 1 次通过**证据（`dev:bff` 在线 + `llmConfigured:true`）。

5. **E2E-AI-09**：容错后断言结构（增长步数 ≥1 + 输入恢复 + 无 alert）+ 带 BFF live
