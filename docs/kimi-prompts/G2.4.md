# PM 裁决（施工与 QA 验收均以本节为准）

## 裁决①：状态机纪律沿用——TRANSITIONS 表仍不可改，本 G 不碰状态接线

G2.3 收口输入①：4 处表缺口走「查表静默跳过 + store 兜底」，接线须遵守查表预判纪律。
G2.4 是**纯渲染层切片**，不得改 `useAssistantStore` 的状态接线逻辑、不得发 machine 事件、
不得新增 AssistantState。若渲染需求撞上表缺口（预期之外的场景）→ 报告 §三并停下等裁决，
**私改即返工**（同 G2.3 纪律）。

## 裁决②：兜底机制回归网不得弱化（G2.3 收口输入②）

G2.3 兜底机制（缺口查表跳过 + store 直设终态 + 忙碌态续跑）的回归网 =
`useAssistantStore.test.ts` 11 条 + `assistantMachine.test.ts` 11 条（实测口径）全绿是硬
门槛。本 G 若须动 `types/assistant.ts` 或 store（仅限类型扩展，如消息挂结构化输出），
**只增不改**，存量用例断言零弱化。注：G2.3 报告 §五「store 28 条」为助理渲染域合计旧
口径，以本工单实测文件口径为准，数字差异挂 G4.3 校正。

## 裁决③：ToolCallPanel 与 uiRegistry 并存——过程归面板，结果归注册表（G2.3 收口输入④）

- **ToolCallPanel 本 G 零改动**（G2.3 签核锁定的 INT-AI-03 回归网绑其四要素与 4 条单测）：
  工具执行**过程**（工具名 / 参数 / 三态 / 耗时、160 字符结果摘要留痕）仍由它表达。
- **uiRegistry 负责工具输出**的富渲染：按 `tool-${toolName}` 白名单分发，输入 =
  消息上 `ToolCallInfo` 的 `output` / `error`（渲染数据源与 G2.3 一致 = 消息 toolCalls，
  不读 machine log、不消费 part 流）。
- 气泡内渲染顺序：ReasoningBlock → ToolCallPanel（过程） → **uiRegistry 卡片（结果）** →
  StreamingText（最终文字）。两者职责切分写死，QA 按此验收。

## 裁决④：placeOrder / ApprovalCard 仅静态占位（G2.3 收口输入⑤，防越界）

- placeOrder 工具**物理不存在**，live 不会产出 `tool-placeOrder`；注册表key先占位只为
  防协议漂移。本 G `tool-placeOrder` → ApprovalCard **静态占位**：仅渲染订单摘要占位
  文案（如「审批功能即将上线」），按钮禁用或不给按钮（coder 定，单测锁形态）。
- **禁止**：任何审批交互逻辑、`addToolApprovalResponse`、machine 事件、订单/审批类型
  定义——全部 G3.2 / G3.3。类型层面仅允许 `ApprovalCard` 组件 props 的占位定义。

## 裁决⑤：白名单安全边界（design §7，验收硬条款）

- 注册表 value 是「渲染决策」而非单个组件；一个 key 可分流到多个组件（命中 / 空结果 /
  失败三分支）。
- **未注册 toolName（含 dynamic tool call）→ 一律降级 fallback 文本**（如
  「暂不支持展示该工具的结果」），绝不渲染任意组件、不渲染任意 HTML、不把 LLM 原始
  输出当代码执行（8/31 报告 Generative UI 安全边界三件套）。
- 输出入 registry 前**必须过 zod 校验**（schema 镜像存量 Product 契约，见「现状」）；
  校验失败 → 内联错误指示（UT-REG-03），不静默渲染坏数据。

## 裁决⑥：气泡内窄宽度列数——PM 拍板 2 列，wrapper 覆盖（收口输入⑥）

- design §7 已知风险称 `.grid`「在气泡窄宽度内退化为 1 列」——**实测不成立**：
  `ProductGrid.module.scss` 媒体查询是**视口宽度**驱动（1200/768/480 → 4/3/2/1 列），
  非容器查询；1280 视口下气泡内反而是 4 列窄卡。此 design 描述偏差挂 G4.3 校准。
- 本 G 拍板：气泡内 ProductGrid 目标 **2 列**。实现 = assistant 侧 wrapper class
  覆盖 `grid-template-columns`（如 `.toolGrid { grid-template-columns: repeat(2, minmax(0,1fr)); }`
  ，特异性高于媒体查询，全视口恒定 2 列），**不改进存量 ProductGrid.module.scss 本体**。
- E2E 断言计算样式列数 = 2（辅助验收「列数已确认」，见验收 4）。

## 裁决⑦：design §7 注册表示例的数据形态偏差——registry 输入 = ToolCallInfo（缺口登记）

design §7 示例签名是 `(part: ToolPart) => ReactNode`（官方 part 形态），但 G2.3 已确立
渲染数据源 = 消息 `toolCalls`（`ToolCallInfo`），chatApi 透传 chunk 后 store 落
`toolCalls`，**part 流在前端不落形态**。本 G registry 实际签名以
`{ toolName, output, error? }`（取自 ToolCallInfo）为输入；design §7 代码示例的校准
挂 G4.3 文档回写欠账（连同裁决⑥ 的媒体查询描述、UT-REG-01「JSON Schema」措辞——
工程实际用 zod 运行时校验，视为同义）。

# 要做的事

## 1. `registry/uiRegistry.tsx`（白名单分发，design §7 位置）

- 导出渲染决策注册表：`Record<string, (call: ToolCallOutput) => ReactNode>`（签名按裁决⑦），
  输入类型从 `types/assistant.ts` 的 `ToolCallInfo` 解耦取 `{ toolName, output, error? }`。
- 注册三个 key 的分支决策：
  - `tool-searchCatalog`：`output.error` 存在 → `<ToolError />`；`items.length === 0` →
    存量 `<EmptyState />`；否则 → 存量 `<ProductGrid>` + N 个存量 `<ProductCard>`，
    grid 外包裁决⑥ 的 wrapper class（覆盖 2 列）。
  - `tool-getProductDetails`：`output.error` 存在 → `<ToolError />`；否则 `<PriceBreakdown product />`。
  - `tool-placeOrder`：`<ApprovalCard placeholder />` 静态占位（裁决④）。
- 输出 zod 校验：定义 `productSchema`（镜像 `Product` 契约）与 `searchCatalogOutputSchema`
  （`{ items: productSchema[], total: number }`）等，**校验失败 → 内联错误指示组件**
  （不重定向、不静默吞）。
- 未注册 key → fallback 文本（纯文本节点，如「暂不支持展示该工具的结果」）。

## 2. 新组件（`components/`，样式仿存量 scss module 惯例，均含 RTL 单测）

- `ToolError.tsx`：轻量错误卡（`message: string`，role 语义自定但**禁止 `role="alert"`**，
  不得破坏 E2E-AI-06~08/12/13 的 alert 计数断言）。
- `PriceBreakdown.tsx`：价格 / 计价方式 / 拆分项展示；货币口径与存量一致（`$` +
  PRICING_LABEL 语义，复用 `catalog/types/product.ts` 的 `PRICING_LABEL`）。
- `ApprovalCard.tsx`：**静态占位**（裁决④）——占位文案 + 禁用态按钮或不给按钮；
  组件 props 类型占位定义可以存在，但不得含审批交互逻辑。
- （可选）错误指示组件：schema 校验失败的 inline 指示，coder 定形态（可与 ToolError 复用）。

## 3. ChatPanel 接线（唯一改动点）

- assistant 气泡内、ToolCallPanel 之后挂 registry 渲染：遍历 `message.toolCalls`，
  每个有 `output` 或 `error` 的 call 过 `uiRegistry` 分发渲染（过程态 call 无输出，
  不渲染卡片，只有 ToolCallPanel 过程卡）。
- 智能滚动 / aborted / error 横幅 / badge 存量逻辑零改动。
