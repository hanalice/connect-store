# PM 裁决（施工与 QA 验收均以本节为准）

## 裁决①：审批 pending 遇流错误 → 保位 await_human（预拍板落地）

- 主流 catch：`approval.phase === 'pending'` 时**不回写 error**、不清 approval——
  停驻 await_human，审批卡保留（server 侧审批仍有效，决策/取消的续跑是新请求，不
  依赖已死的流）；卡内提示「操作失败，可重试」最小形态（coder 定，单测锁）。
- 审批回放（runApprovalReplay）与 cancelOrder 的 catch **同纪律**：pending 保位，
  错误不回写 error 态；非 pending 的既有 error 路径不变。
- 验收：单测断言「审批 pending 中流错误 → status 仍 await_human + approval 保留 +
  banner 不现」；E2E-AI-24 浏览器侧实证。

## 裁决②：重试按钮语义 = RETRY + 重发原消息新回合

- error 横幅加「重试」按钮：store 在 error 落态时存 `lastFailedText`（仅非 pending
  路径）；点击 = `sendMessage(lastFailedText)`——复用既有「error 先 RETRY 再
  USER_SEND」两事件路径（G2.3 裁决①），**不新造机器事件**。
- aborted 横幅**无重试按钮**（aborted 三约束①：无重试语义），恢复 = 直发新消息
  （表内 #20 边）；aborted 横幅文案沿用「已停止生成，可继续发送新消息」。

## 裁决③：降级提示挂点 = error / aborted 双横幅

- 两横幅附文本链接「或回目录手动选购 →」（`#/` 目录页，react-router Link）；仅这两
  处，不扩散到审批卡 / 工具错误（工具错误有自身恢复路径）。

## 裁决④：A11Y-05 + INT-HITL-04 fake-timer 归本 G（PM 归属裁决）

- **A11Y-05 审批卡焦点管理归 G3.4 附带项**（G3.3 签核时挂 G4.1，现改判）：① G3.4 后
  Implementation 收官，再无前端功能 G——拖到 G4.x = 收官后回头改组件，违反「G4 只
  收口不施工」惯例；② 焦点管理与 G3.3 composer 锁定同属 await_human 交互可达性面，
  是本 G 的自然补全；③ 量小（焦点移入/归还 effect + 断言）。G4.1 保持纯测试矩阵。
- 最小形态：审批卡出现时焦点移入卡内首个可交互元素；决策/取消后归还 composer；
  单测断言 document.activeElement；E2E 不断言焦点（Playwright 焦点断言易 flake，
  单测锁即可）。
- INT-HITL-04 fake-timer 归零用例同归本 G（`vi.useFakeTimers` 推进 1s 级 interval
  到归零，断言禁用态 + 「已过期，请重新发起」）。
