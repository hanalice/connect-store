# PM 裁决（施工与 QA 验收均以本节为准）

## 裁决①：lint 验收命令措辞（G2.4 §三 措辞问题收口）

验收与自测统一写 `npm run lint`——脚本本身已内置 `--max-warnings 0`；经 npm 透传叠加
`--max-warnings 0` 会把裸 `0` 当文件 pattern 误报（PM 已裁定，后续工单同口径）。
本 G 不改 lint 脚本、不改 package.json。

## 裁决②：状态机纪律与回归网硬门槛

- `assistantMachine.ts(.test.ts)` 本 G **零改动**（购物车不进状态机，无新
  AssistantState）；`types/assistant.ts` 预计零改动（`ToolCallInfo` 已够用），若确需
  扩展只增不改。
- 兜底回归网 = `useAssistantStore.test.ts` 11 条 + `assistantMachine.test.ts` 11 条
  原样全绿是硬门槛；`useAssistantStore` 允许**增量接线**（见裁决④），存量断言零弱化。

## 裁决③：persist 方案拍板（design 留白）

- 存储键名 = **`clo-cart`**（沿用 `usePreferenceStore` 的 `clo-` 前缀惯例）；存储介质 =
  persist 默认 localStorage（纯 CSR Vite 应用，无 SSR 问题）。
- `partialize`：只 persist `items`（`CartItem[]`），**不 persist UI 态**（drawer 开关、
  步进中间态不持久化，刷新后 drawer 默认关闭）。
- 恢复时机 = persist 自动 rehydrate（store create 时同步完成）；写入即持久化，无手动
  落盘调用。
- 测试兼容：vitest jsdom **有** localStorage；用例间必须隔离——`beforeEach` 清
  localStorage 并重置 store 到初始态（`useCartStore.setState(initialState)`），防跨
  用例污染；persist 恢复用例用「写入 → 重挂载 / 重新 create 断言 rehydrate」或
  `persist.rehydrate()` 模拟刷新，coder 定具体手法但用例必须真实经过 persist 层
  （不许只测内存态冒充 persist）。

## 裁决④：addToCart 前端接线形态——store 写入走 assistant store，展示走 registry 新 key

- **写购物车（副作用）**：在 `useAssistantStore.ts` 的 `tool-output-available` 分支
  **增量接线**——`chunk.toolName === 'addToCart'` 且输出过 zod 校验（镜像
  `{ productId, quantity, product }` 契约，复用 G2.4 `productSchema`）→
  `useCartStore.getState().add(product, quantity)`；`{ error }` 回执**不写**购物车。
  依赖方向单向：assistant → cart（cart 不得 import assistant）。
- **展示（纯渲染）**：uiRegistry 新增 key `tool-addToCart` → 新组件 **CartConfirmCard**
  （轻量：✓ 已加入 N 件「标题」+ 该条目小计 + 「查看购物车」按钮）；决策函数保持纯函数
  零副作用（G2.4 模式延续），**store 写入只发生在 assistant store**。
- 不采用「store 监听 / subscription」方案：隐式依赖渲染时机、双写难审计；显式接线可
  单测、可记日志。

## 裁决⑤：CartDrawer 挂载与打开触发（design 留白拍板）

- design §7 给了 cart 目录三文件但**未定义挂载点与触发**——PM 拍板：本 G 挂
  **`AssistantPage`**（assistant 域是唯一消费点；catalog 页接入不在本 G，见「明确不做」）。
- 触发双通道：① **加购回执成功 → drawer 自动打开**（design §4「UI 展示加购成功」的
  直接落地）；② 面板头部 **cart badge（条目数）点击开关**（关闭后可重开）。
- drawer 含 disabled「去结算（即将上线）」占位按钮（design §3「下单入口」字样预留，
  交互归 G3.3，同 G2.4 ApprovalCard 静态占位套路，防越界）。

## 裁决⑥：合计口径与 CartItem 形态

- `CartItem = { product: Product; quantity: number }`（挂完整 Product 便于渲染，
  与 G2.4 复用组件同契约）。
- 合计 = `Σ(product.price × quantity)`：Free / View Only 商品 price 非 0（G2.1 价格
  语义），小计统一按 price 计，展示与 ProductCard 的 `$x.xx` 口径一致。
- 重复加购同商品 = 数量合并（UT-CART-01），不新增条目行。
