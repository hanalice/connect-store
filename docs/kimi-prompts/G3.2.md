# 目标

交付 HITL 审批**后端**切片（ADR D9 分层之两层一起落地）：

- **协议层**：`streamText` 挂 SDK 原生 `toolApproval`（placeOrder 恒 `'user-approval'`）+
  `experimental_toolApprovalSecret` 签名（绑定服务端签发的 toolName + toolCallId + input，
  防客户端伪造审批绕过 HITL）。
- **业务状态层**：`orders.ts` 订单表（pending / approved / rejected / expired + issuedAt +
  TTL + **按 orderId 查询** + 审计日志）+ `approvals.ts`（策略回调 + 签发时刻表 + TTL 判定）。

完成标准（todo G3.2 行）：curl 走通 pending → approve / reject / edit；超时 → expired；
未审批直接下单被拦截（**API-AI-01**）。编号映射：API-AI-04（按 orderId 查询）、
API-AI-05（TTL 过期）、API-AI-06（伪造审批拦截）同本 G 落地。

**本 G 后端切片：前端 `src/` 与 `e2e/` 零改动**（ApprovalCard 交互是 G3.3），E2E 零新增。

# PM 裁决（施工与 QA 验收均以本节为准）

## 裁决①：下单计价以 server 实时数据为准（G3.1 §五 预警落地）

placeOrder execute **不得以请求体或前端持久化快照的金额为准**：按 cart 条目 `productId`
查 `server/data/products.ts` 快照**现价**重新计价（`amount = Σ unitPrice × quantity`，
条目级 unitPrice 取快照价并落入订单记录）；条目 id 在快照中不存在 → 拒绝执行并返回
`error`。前端 `clo-cart` 的持久化价格是加购时刻快照、价格变更不回溯（G3.1 §五），
本裁决切断该风险面。验收：单测构造「快照价变更后下单」断言金额 = 新价。

## 裁决②：协议字段以 ai@7 类型定义为准（G3.1 §六 措辞收口）

工单及代码涉及 chunk / 协议字段（`tool-approval-request` / `tool-approval-response` /
`execution-denied` 等）**一律以安装的 `ai` 包类型定义核对**（node_modules/ai/dist/
index.d.ts），禁止凭记忆写字段名（G3.1 已发生 `chunk.toolName` 措辞错误一例）。
G3.3 前端接线措辞统一「从已登记 toolCall 取 toolName」。streamText 是否支持
`toolApproval` / `experimental_toolApprovalSecret` 选项、选项挂法（settings 还是顶层），
**施工前先核安装版本类型**（design §6.2 声称支持 ToolLoopAgent / streamText /
generateText，但以类型定义与最小实测为准）。

## 裁决③：金额阈值分级拍板——默认 $50 可调，placeOrder 恒 'user-approval'

- design §4 只给了分级原则 + 官方同构示例（`amount > 1000 ? 'user-approval' : undefined`），
  **未给项目阈值**——PM 拍板：默认阈值 = **$50**（env `APPROVAL_AMOUNT_THRESHOLD`，
  缺省 50，可调），理由：快照价格带宽（1~10000），$50 足以演示大小额两侧。
- **placeOrder 恒为 `'user-approval'`**（design §4「不可逆恒审批」是安全底线，优先于
  官方示例的 `undefined` 自动放行分支——本 Showcase 不下放任何不可逆副作用）。
- 阈值分级的**可运行演示**落在 server 单测：以**临时可逆假工具**（仅测试内构造，
  不进生产注册表）走通官方同构分支 `amount > threshold → 'user-approval' / ≤ →
undefined`，证明策略函数机制真实可运行；**不新增生产工具**。

## 裁决④：TTL = 300 秒 + 签发时刻表结构（对齐 G0.4 实测口径）

- TTL = **300,000ms（5 min）**，与 `ttl-approval-experiment.md` 实测口径逐字一致（代码
  常量，注释标注可调；不进 env）。
- **签发时刻表**（`approvals.ts` 内存 `Map`）：`toolCallId → IssuanceRecord`，
  `IssuanceRecord = { orderId, issuedAt, expiresAt }`——策略回调**首次**对某 toolCallId
  返回 `'user-approval'` 时写入（签发）。
- 过期判定在**复放时**（策略回调被 SDK 重估）：`now > expiresAt` →
  `{ type: 'denied', reason: 'approval expired' }`（G0.4 实测 SDK 产出
  `execution-denied`，工具执行 0 次）；未过期 → `{ type: 'approved' }`。
- `now` **可注入时钟**（仿 A9 machine 注入时钟模式），vitest 假时钟推进，禁止真实
  sleep（G0.4 实验即用可控时钟，300,001ms 边界值照此构造）。

## 裁决⑤：live 可达性拍板——注册进注册表，「hang but safe」，前端零改动

- placeOrder **注册进 `toolRegistry`**（A7 唯一一份；`chat.ts` 的 `tools: toolRegistry`
  自动带上；`toolApproval` + `experimental_toolApprovalSecret` 挂进 `streamText`）。
- live 影响：用户对话触发下单 → SDK 拦截发 `tool-approval-request` → 前端（G3.3 未接）
  无法回应 → **会话停驻但不产生任何未授权副作用**（实验证实：无审批 = 执行 0 次）——
  「hang but safe」属预期行为，G3.3 闭环。uiRegistry `tool-placeOrder` 静态占位不渲染
  （无 tool output 不触发卡片），无需处理。
- **缺 `APPROVAL_SECRET` 的安全失败模式**：未配置 secret 时 placeOrder 策略直接
  `{ type: 'denied', reason: 'approval service not configured' }`（工具不执行）——
  宁可拒绝不可用，不可无签名放行。演示/验收前须配 `APPROVAL_SECRET`
  （`openssl rand -base64 32`，运维前置，写 .env 但不读不回显）。

## 裁决⑥：订单表结构 + 查询端点 + edit 语义 + 惰性过期

- `orders.ts`：`Map<orderId, OrderRecord>`；`OrderRecord = { orderId, toolCallId,
items: { productId, title, quantity, unitPrice }[], amount, status:
'pending'|'approved'|'rejected'|'expired', issuedAt, expiresAt, decidedAt?,
audit: AuditEntry[] }`；`AuditEntry = { ts, event: 'issued'|'approved'|'rejected'|
'expired'|'executed', detail? }`。
- 查询端点 **`GET /api/orders/:orderId`**（design §8「按 orderId 查询」、API-AI-04）：
  返回当前状态；**惰性过期**（design §6.3 ②）——查询时若 `pending` 且已超 TTL →
  落 `expired` 并记审计后返回。未知 orderId → 404（不暴露存在性）。
- **edit 语义**（design §6.1 出边的后端投影）：edit = 旧 order 标记 `rejected`
  （detail 注明用户修改）+ 修改后的购物车触发**新 toolCall** → 新 orderId 新 pending；
  状态枚举**锁定四态**（无 edited），curl 走通「旧单 rejected + 新单 pending」即验收。

## 裁决⑦：白名单互斥升级为代码级检查（A7 预警收口）

`env.ts:15` / `index.ts:37` 的「placeOrder 永不入白名单」目前是**注释级约束**，而
`parseToolsDirectAllow` 的「白名单 ∩ 注册表 key」机制在 placeOrder 注册后会自然放行
——必须升级：**env.ts 增加审批门控黑名单**（`APPROVAL_GATED = ['placeOrder']`，
交集结果再剔除），即使 `TOOLS_DIRECT_ALLOW` 显式写入 placeOrder 也无效；`index.ts`
注释同步声明。本 G **允许改 `env.ts` 仅此一处**（+ `.env.example` 追加
`APPROVAL_SECRET` / `APPROVAL_AMOUNT_THRESHOLD` 说明）。验收：server vitest 断言
「白名单含 placeOrder 时直调仍 404」+ curl 实证（API 级互斥）。
