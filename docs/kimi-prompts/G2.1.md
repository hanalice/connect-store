# 要做的事

## 1. 冻结快照导出（一次性脚本）

- 新建 `server/scripts/export-products.mjs`（纯 node 运行，零依赖）：fetch 远程
  `/api/data` 全量数组 → 逐条校验字段形状（id/creator/title/pricingOption/imagePath/
  price）→ 落盘 **`server/data/products.json`**（格式化输出，便于 git diff 审阅）。
- `server/package.json` 加 script：`"export:snapshot": "node scripts/export-products.mjs"`。
- **快照格式决定（PM 拍板，依据写明）：用 `.json` 而非 `.ts`**。理由：快照是数据工件
  （全量数组，体量远大于代码文件），与源码分离才能保持「重新导出 = 换一个数据文件」的
  心智模型与可审阅 diff；若塞成 `.ts` 导出常量，数百 KB 数据会被 tsc 类型检查与
  prettier 当源码处理，无任何收益。配套：`server/tsconfig.json` 加
  `resolveJsonModule: true`（NodeNext 下 JSON import 需要），加载处用
  `import products from './products.json' with { type: 'json' }`（Node 22 / tsx 支持）。
- 生成的 `products.json` 加入根 `.prettierignore`（生成物，不参与格式门禁；
  导出脚本本身仍须过 prettier）。
- **运行时不直连远程**（硬约束执行约定）：导出是构建期一次性动作；快照文件随仓库提交。
- 报告须记录：导出日期、商品总条数、三种 pricingOption 各自的条数与 price 分布
  （min/max）——这是「20 刀以内」验收判断的事实基础（View Only / Free 商品的 price
  实际取值以快照为准，如实记录，不得假设）。

## 2. 数据层 `server/data/products.ts`

- 加载快照 + 在快照上**真实执行**过滤 / 排序 / 区间过滤（数据 mock、逻辑真跑，D10）。
- 过滤语义与存量 `filterProducts`（catalogSelectors.ts）**保持同口径**：
  - `query`：trim + lowercase 后对 `title` / `creator` 做子串匹配（OR 关系）；
  - `pricingOption`：精确匹配；
  - 排序：复刻存量 `sortProducts` 三模式语义（default = title A-Z；price-desc =
    PAID 优先组内价格降序；price-asc = VIEW_ONLY 优先组内价格升序；平局 fallback
    title A-Z）；
  - **`maxPrice` / `minPrice`（BFF 侧新增能力，存量前端没有）**：对 `price` 字段做
    **闭区间** `[minPrice, maxPrice]` 过滤；与上述条件为 **AND** 组合。
- 诚实声明（写进代码注释）：仅 title/creator 子串匹配，无同义词扩展、无向量召回
  （design §1.3）。

## 3. 工具定义 `server/tools/`（AI SDK `tool()` 形态，为 G2.3 接入做准备）

- `server/tools/searchCatalog.ts`：入参
  `{ query?, pricingOption?, sort?, maxPrice?, minPrice? }`，Zod schema 校验
  （query 为 string；pricingOption 为 0/1/2 枚举；sort 为
  `'default' | 'price-desc' | 'price-asc'`；maxPrice/minPrice 为 number；
  非法输入由 Zod 给出明确报错）。execute 调数据层真实过滤，返回
  `{ items: Product[], total: number }`。只读、无 HITL（design §4）。
- `server/tools/getProductDetails.ts`：入参 `{ id }`（string，必填）；execute 在快照中
  按 id 查找；命中返回商品，未命中返回明确错误（不要静默返回 null 让 LLM 误以为成功）。
- `server/tools/addToCart.ts`：入参 `{ productId, quantity }`（productId 必填 string；
  quantity 为正整数，Zod `.int().positive()`）。**边界（PM 拍板，依据写明）：G2.1 只做到
  「工具定义 + schema 校验 + 返回回执」** —— execute 校验 productId 存在于快照、
  quantity 合法，返回 `{ productId, quantity, product }` 回执；**不写任何购物车
  状态落点**（购物车 store 接线属 G3.1；依据 = todo.md G3.1 行「`addToCart` 工具
  前端接线」与 design §4 副作用级别「低（可逆）→ 自动执行 + UI 反馈」的分工：
  本 G 交付协议与校验，副作用落点随购物车切片一起交付）。
- `server/tools/index.ts`：导出**唯一一份工具注册表**（toolName → 工具定义），
  dev 直调端点（§4）与未来 `/api/chat` 工具回路（G2.3）共用，避免两份定义漂移。

## 4. dev 工具直调端点 `POST /api/tools/:toolName`

- **设计决定（PM 拍板，依据写明）：采纳新增此端点**。理由：todo G2.1 完成标准要求
  「curl 逐工具验证（含非法输入 → Zod 明确报错）」，而 `/api/chat` 接入工具回路属
  G2.3——若不加 HTTP 落点，curl 验收在本 G 物理上不可执行，只能用单测替代，与完成
  标准的字面要求不符。定位为 **dev / QA 验收端点**（G2.3 后保留作调试用），不承担
  生产语义。
- 行为约定：
  - toolName 白名单 = 工具注册表的 key；未知名 → **HTTP 404** + JSON 错误；
  - body = 工具入参 JSON；先经该工具 Zod schema `safeParse`：失败 → **HTTP 400** +
    JSON（含 Zod issues 数组，文案明确指认非法字段与期望类型）；成功 → 执行 execute，
    **HTTP 200** + 工具返回结果 JSON；
  - JSON 解析失败 → 400；body 大小限制沿用 `/api/chat` 的 1 MB 口径（413）；
  - 挂载在 `server/index.ts`，**不动现有 `/health` 与 `/api/chat` 行为**。

## 5. server 侧 vitest 最小基建 + 单测

- **查证结论（PM 已核实）**：`server/` 无任何测试基建（无 vitest 依赖、无 `test`
  script）。最小方案：`server/` devDep 加 `vitest`（版本与根项目对齐，装前查根
  package.json 实测版本）；script 加 `"test": "vitest run"`；**不需要 vitest 配置文件**
  （Node 环境为默认，无 jsdom / setup 需求）；`tsconfig.json` include 扩为 `["**/*.ts"]`。
- server 侧测试**独立于根 38 个**，不进根 `npm test`（根 pre-commit 只跑根三件套；
  server 有自己的 `npm test`，验收时分别跑）。
- 单测用例（vitest，`server/tools/` / `server/data/` 旁挂 `.test.ts`）：
  - 过滤逻辑：query 子串（title / creator / 大小写 / trim）；pricingOption 精确匹配；
    三种排序模式各一条；**maxPrice/minPrice 闭区间边界值**（price 恰等于 min / max
    应命中）；多条件 AND 组合；
  - Zod schema：各工具至少一条非法入参用例（如 `maxPrice: 'abc'`、`quantity: 0`、
    缺 `id`）断言 safeParse 失败且 issue 指向对应字段；
  - execute：searchCatalog 空结果返回 `{ items: [], total: 0 }`；
    getProductDetails 未命中 id 返回明确错误；addToCart 对不存在 productId 报错。
- 快照较大时，单测用**小夹具**（测试内构造几条 Product 注入过滤函数）而不是全量
  快照，保证测试快且断言精确；过滤函数需支持注入数据源（参数传入，不硬读模块级快照）。

# 验收（逐条实测并贴原始输出）

前置：`cd server && npm run export:snapshot` 落盘快照；`npm run dev` 起 BFF（8787）。

1. **「20 刀以内」maxPrice 过滤正确性**（对应 API-AI-02 价格区间语义）：

   ```bash
   curl -s -X POST localhost:8787/api/tools/searchCatalog \
     -H 'content-type: application/json' -d '{"maxPrice":20}' \
     | jq '{total, allWithin: ([.items[].price] | all(. <= 20))}'
   ```

   → `allWithin` 为 `true` 且 `total > 0`（若 total 为 0，报告须用 §1 的 price 分布
   数据解释原因，不得隐瞒）。

2. **非法输入 → Zod 明确报错**：

   ```bash
   curl -s -i -X POST localhost:8787/api/tools/searchCatalog \
     -H 'content-type: application/json' -d '{"maxPrice":"abc"}'
   ```

   → **HTTP 400**；body 为 JSON，含 issues 数组，首条 issue 明确指认 `maxPrice`
   字段与期望类型 number（贴原始输出，文案以 Zod v4 实际报错为准）。

3. 价格区间 AND：`{"minPrice":10,"maxPrice":20}` →
   `[.items[].price] | all(. >= 10 and . <= 20)` 为 true。
4. pricingOption：`{"pricingOption":1}` →
   `[.items[].pricingOption] | all(. == 1)` 为 true。
5. 排序：`{"sort":"price-desc","pricingOption":0}` → 返回 items 的 price 序列
   非升（jq 构造校验，贴命令与输出）。
6. query 子串：从快照取一个真实 title 子串作为关键词（报告中说明取值与预期命中数），
   `{"query":"<关键词>"}` → 所有返回项的 title 或 creator 含该子串（jq 校验）。
7. getProductDetails：合法 id → 200 返回该商品且 id 一致；不存在的 id → 明确错误
   （非 200 或带错误字段，不得静默 null）；缺 `id` 入参 → 400 Zod 报错。
8. addToCart：合法 `{"productId":"<真实id>","quantity":2}` → 200 回执含
   product/quantity；`{"productId":"<真实id>","quantity":0}` → 400 Zod 报错；
   不存在的 productId → 明确错误。
9. 未知工具：`curl -i -X POST localhost:8787/api/tools/nope -d '{}'` → **404**。
10. `cd server && npm test` → vitest 全绿（贴用例数与耗时）；`npx tsc --noEmit` → 0 错误。
11. 根三件套：`npm test` **38 通过零回归**；`npm run lint` **0 warning**；
    `npm run format:check` 通过；`npm run build` 通过。
12. （仅当 §6 可选项被确认）前端 dev 下 `curl localhost:5173/<商品 data 路径>` 与
    BFF 快照逐字节一致（或条数与首尾条 id 一致），且根 38 测试仍零回归。
