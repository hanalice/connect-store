# 要做的事

1. **依赖**：在 `server/` 内装 `@ai-sdk/deepseek@^3`（官方 provider，实测 latest 3.0.70）。
2. **`server/chat.ts`**：新建路由，`POST /api/chat`。
   - provider：`createDeepSeek({ apiKey: env.llmApiKey, baseURL: env.llmBaseUrl })` → `deepseek(env.llmModel)`
   - 请求体：`{ messages: UIMessage[] }`；用 zod 做**最小结构校验**（`role` + `parts` 数组），不要引入 `validateUIMessages` 之类未确认存在的能力
   - 调 `streamText({ model, messages: await convertToModelMessages(messages) })` —— **不传 tools**（tools 属 G2）
   - 响应：`createUIMessageStreamResponse({ stream: toUIMessageStream({ stream: result.stream }) })`
   - ⚠️ 上述 API 形态来自官方 v7 文档；**若与 `node_modules/ai` 的类型定义不符，以 `.d.ts` 为准**并在报告中说明差异（例如 `instructions` 还是 `system`）
3. **`server/index.ts`**：挂载 chat 路由（`app.route('/api', ...)` 或 `app.post('/api/chat', ...)`），**不要改动现有 `/health` 行为**。
4. **缺配置时的明确失败**：`llmConfigured === false` 时，`/api/chat` 立即返回 **HTTP 503** + JSON 错误（如 `{ error: 'LLM not configured' }`）；**不要**静默降级、不要返回 200 空流、不要让服务崩溃。`/health` 仍须可访问。
5. **请求体大小限制**（design §8）：对 `/api/chat` 限制 **1 MB**（可用 `hono/body-limit`，或自行校验 `Content-Length`）；超限返回 **413**。这是 G1.1 明确留到本任务的项目。
6. **上游错误处理**：上游超时 / 4xx / 5xx 时，返回**标准化的 SSE error 事件**并正常结束连接，不让浏览器挂起（对应 `API-AI-03`）。
