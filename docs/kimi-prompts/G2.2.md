# 两个 design 缺口的裁决（PM 拍板，施工与 QA 验收均以本节为准）

design §5 是**唯一施工文档**（kimi-prompts README 四文档关系表：design = 施工依据的最终
解释权）；`docs/test_cases.md` 与 `types/assistant.ts` 的措辞均从属。

## 缺口①：`thinking → streaming` 与 `tool_result → streaming` 无对应事件 → 新增 `STREAM_START`

- 现象：design §5 事件枚举 11 个（`USER_SEND` / `TOOL_CALL` / `TOOL_RESULT` / `STREAM_END`
  / `APPROVAL_REQUEST` / `APPROVE` / `REJECT` / `EDIT` / `USER_ABORT` / `RETRY` / `ERROR`），
  而 mermaid 中 `thinking → streaming`（LLM 直接回复）与 `tool_result → streaming`
  （生成最终回复）两条边在枚举中没有触发事件。
- 依据：design 自声明「状态机以转换表 `(state, event) → next` 驱动」且日志 entry 的
  `event` = 触发事件枚举——**转换集与事件表本应一一对应**，缺事件则这两条边在表驱动
  架构下无法表达，也违反了日志口径。
- 裁决：新增 **`STREAM_START`** 事件，枚举扩为 **12 个**。这是对 design §5 枚举的
  **最小补全**：不引入新状态、不删改任何已有边、不影响其余 10 个事件的语义。
- design 文档变更日志**留待 G4.3 收口时回写**（本 G 不改 design 文档，见「明确不做」）。

## 缺口②：`STREAM_ERROR` vs `ERROR`（UT-ASM-09）→ 统一 `ERROR`

- 现象：UT-ASM-09 描述用 `STREAM_ERROR`，design §5 枚举用 `ERROR`。同类问题还有
  UT-ASM-02 的 `CALL_TOOL` vs design 枚举的 `TOOL_CALL`。
- 依据：design 是唯一施工文档，test_cases.md 措辞从属；且 `ERROR` 还需覆盖
  `tool_calling → error`（工具失败）边，`STREAM_ERROR` 命名反而过窄。
- 裁决：统一用 **`ERROR`** 与 **`TOOL_CALL`**。test_cases.md 的上述措辞差异随 G4.3
  文档收口时再校准，本 G 不改 test_cases.md。

## 2. 类型与事件枚举（erasableSyntaxOnly：禁止 `enum` 关键字）

```ts
export type AssistantState =
  | 'idle'
  | 'thinking'
  | 'tool_calling'
  | 'tool_result'
  | 'streaming'
  | 'await_human'
  | 'done' // 唯一终态
  | 'error'
  | 'aborted';

// const 对象 + type union（erasableSyntaxOnly 下 enum 不可编译）
export const ASSISTANT_EVENT = {
  UserSend: 'USER_SEND',
  ToolCall: 'TOOL_CALL',
  StreamStart: 'STREAM_START', // 缺口①裁决新增
  ToolResult: 'TOOL_RESULT',
  StreamEnd: 'STREAM_END',
  ApprovalRequest: 'APPROVAL_REQUEST',
  Approve: 'APPROVE',
  Reject: 'REJECT',
  Edit: 'EDIT',
  UserAbort: 'USER_ABORT',
  Retry: 'RETRY',
  Error: 'ERROR',
} as const;
export type AssistantEvent = (typeof ASSISTANT_EVENT)[keyof typeof ASSISTANT_EVENT];
```

- 9 状态口径以 design §5 为准：7 主体 + 2 附加；`done` 是**唯一终态**（无任何出边，
  任意事件打到 `done` 都走拒绝路径）。
- 导出 `ASSISTANT_STATES` / `ASSISTANT_EVENTS` 常量数组（`as const`），供遍历与单测断言
  表规模用。

## 3. 转换表（数据与执行逻辑分离）

- 导出表驱动数据（形态示例，可按 prettier 排版调整）：

```ts
export const TRANSITIONS: Readonly<
  Record<AssistantState, Readonly<Partial<Record<AssistantEvent, AssistantState>>>>
> = {
  idle: { user_send: 'thinking' }, // 键用 ASSISTANT_EVENT 值，此处仅为示意
  // ... 共 20 条合法 (state, event) → next
};
```

- **20 条合法转换**以 design §5 mermaid 逐条翻译（= 19 个唯一状态对，其中
  `await_human → tool_calling` 由 `APPROVE` / `EDIT` 两个事件共享）：

| #   | from         | event            | to           | mermaid 依据        |
| --- | ------------ | ---------------- | ------------ | ------------------- |
| 1   | idle         | USER_SEND        | thinking     | 用户发送消息        |
| 2   | thinking     | TOOL_CALL        | tool_calling | LLM 请求工具        |
| 3   | thinking     | STREAM_START ★   | streaming    | LLM 直接回复        |
| 4   | tool_calling | TOOL_RESULT      | tool_result  | 工具执行完成        |
| 5   | tool_result  | TOOL_CALL        | tool_calling | 需要更多工具        |
| 6   | tool_result  | STREAM_START ★   | streaming    | 生成最终回复        |
| 7   | streaming    | APPROVAL_REQUEST | await_human  | AI 提议副作用操作   |
| 8   | streaming    | STREAM_END       | done         | 回复完成            |
| 9   | await_human  | APPROVE          | tool_calling | approve → 执行下单  |
| 10  | await_human  | REJECT           | thinking     | reject → 反馈给 LLM |
| 11  | await_human  | EDIT             | tool_calling | edit → 修改后继续   |
| 12  | await_human  | USER_ABORT       | aborted      | 用户取消订单        |
| 13  | thinking     | USER_ABORT       | aborted      | 用户点停止          |
| 14  | streaming    | USER_ABORT       | aborted      | 用户点停止          |
| 15  | tool_calling | USER_ABORT       | aborted      | 用户点停止          |
| 16  | tool_result  | USER_ABORT       | aborted      | 用户点停止          |
| 17  | streaming    | ERROR            | error        | 流中断/超时         |
| 18  | tool_calling | ERROR            | error        | 工具失败(重试后)    |
| 19  | error        | RETRY            | idle         | 用户重试            |
| 20  | aborted      | USER_SEND        | thinking     | 用户继续发消息      |

（★ = 缺口①裁决补入的两条边。）初始状态 = `idle`（对应 mermaid `[*] → idle`）。
非法组合 = 表中不存在的 `(state, event)`：9 状态 × 12 事件 = 108 组合，合法 20，
**非法 88**（含 `done` 的全部 12 个事件）。

## 4. 执行逻辑：send() + 非法组合显式拒绝

- 形态示例（等价形态可接受，但偏离须报告）：

```ts
export interface TransitionLogEntry {
  from: AssistantState;
  to: AssistantState;
  event: AssistantEvent;
  tool?: string;
  args?: unknown;
  result?: unknown;
  ts: number; // 转换时刻，取自注入时钟
  durationMs: number; // 该次转换耗时（工具执行场景由调用方传入；默认 0）
}

export interface MachineSendResult {
  state: AssistantState; // 发送后状态；拒绝时 = 原状态不变
  entry: TransitionLogEntry | null; // 成功转换的日志 entry；拒绝时为 null
  rejected: boolean;
}

export function createAssistantMachine(now: () => number = Date.now): {
  readonly state: AssistantState; // 初始 'idle'
  readonly log: readonly TransitionLogEntry[]; // 环形缓冲只读视图，oldest → newest
  send(
    event: AssistantEvent,
    detail?: { tool?: string; args?: unknown; result?: unknown; durationMs?: number },
  ): MachineSendResult;
};
```

- **非法组合显式拒绝（G2.2 核心测试目标）**：返回 `{ state: <原状态>, entry: null,
rejected: true }`，`console.warn` 打出含 `state` + `event` 的明确文案，**状态不变、
  日志不写 entry**（UT-ASM-07 口径：rejected + warning logged + state unchanged）。
- `tool` / `args` / `result` 由 `detail` 透传进日志（如 `TOOL_CALL` 带 tool/args、
  `TOOL_RESULT` 带 result），不校验内容。

## 5. 事件日志：环形缓冲 200 条 FIFO

- 上限 **200** 条；第 201 条起**驱逐最旧**（FIFO）。`log` 视图按 oldest → newest 顺序。
- entry 字段以 design §5 为准：`{ from, to, event, tool?, args?, result?, ts, durationMs }`。
- 时钟可注入（`now` 参数，单测用假时钟断言 `ts` 单调不减）；默认 `Date.now`。

## 6. 单测（≥7 条路径全绿；标题嵌 UT-ASM-xx 编号，09 个编号全覆盖）

- 测试标题格式仿存量惯例 `INT-08: ...`（见 `CatalogPage.test.tsx`）：
  `UT-ASM-01: Direct Response Flow` 等。
- 用例映射（一条用例可覆盖多个编号，但 UT-ASM-01~09 每个都必须有归属用例）：
  - **UT-ASM-01** 直接回复：`idle →(USER_SEND) thinking →(STREAM_START) streaming
→(STREAM_END) done`；断言状态序列、log 记录全部转换。
  - **UT-ASM-02** 单工具：`thinking →(TOOL_CALL) tool_calling →(TOOL_RESULT) tool_result
→(STREAM_START) streaming →(STREAM_END) done`。
  - **UT-ASM-03** 多工具循环：`tool_result →(TOOL_CALL) tool_calling` 再次进入工具，
    log 逐条记录（TOOL_CALL 带 tool/args）。
  - **UT-ASM-04** HITL approve：`streaming →(APPROVAL_REQUEST) await_human →(APPROVE)
tool_calling →(TOOL_RESULT) tool_result →(STREAM_START) streaming →(STREAM_END) done`。
  - **UT-ASM-05** reject：`await_human →(REJECT) thinking`。
  - **UT-ASM-06** edit：`await_human →(EDIT) tool_calling`。
  - **UT-ASM-07** 非法拒绝（≥2 例：如 `done` + 任意事件、`idle` + `TOOL_RESULT`）：
    断言 `rejected === true`、状态不变、`console.warn` 被调用（`vi.spyOn`）、log 不写。
  - **UT-ASM-08** 环形缓冲：触发 >200 次合法转换（可用 `aborted →(USER_SEND) thinking
→(USER_ABORT) aborted` 交替循环），断言 `log.length === 200`、首条 = 第 n−199 条、
    FIFO 顺序、`ts` 单调不减。
  - **UT-ASM-09** 错误恢复：`streaming →(ERROR) error` 与 `tool_calling →(ERROR) error`，
    再 `error →(RETRY) idle`。
- **aborted 必含**：四条「用户点停止」边（thinking / streaming / tool_calling /
  tool_result + USER_ABORT → aborted）+ `await_human + USER_ABORT → aborted` +
  `aborted + USER_SEND → thinking` 恢复。
- 表规模断言（1 条）：遍历 `TRANSITIONS` 计数 === 20（防施工期增删边）。
- 新增后根测试 **38 → ≥45**。
