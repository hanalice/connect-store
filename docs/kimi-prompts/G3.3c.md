# 目标

修复 H2 走查捕获的两个 cart 一致性缺口（用户已确认定性：UI 状态不一致缺陷，非语义
争议）——assistant→cart 只接了「加购」半根线，edit / 订单执行两个事件点从未施工：

1. **edit 同步**：审批卡 edit 改数量 / 移除条目后（G3.3b 方案 B），订单链路认修改、

2. **执行扣减**：placeOrder 执行回执到达后购物车不清 / 不扣减（placeOrder 不碰

一剂药全在**客户端 store 层**（machine / server 零改动，用户既定方向）。

# PM 裁决（施工与 QA 验收均以本节为准）

## 裁决①：edit 同步规则（align 语义）

- **时机**：`editOrder` 确认点（与 superseded 投影同处），数据 = 修改后 draft items
  （`ApprovalItem[] {productId, quantity}`）。
- **规则**：cart 已有行按 productId 对齐数量；**cart 有而订单不再含的条目 → 删行**；
  **cart 没有而订单含有的 productId → 跳过不补行**（cart 保持「用户亲手加购」语义，
  订单链路代写购物车越界）。

## 裁决②：执行扣减规则（deduct 语义）

- **数据源 = 客户端被 approve 那张卡的 items（审批记录）**——placeOrder 输出帧
  `{orderId, orderNumber, amount}` **无 items 字段**，不得以输出帧为据；按 toolCallId
  关联本 store 审批记录取 items。
- **规则**：`cartQty − orderQty`，结果 ≤ 0 → 删行（clamp，不报错、不产生负数数量）。
- **查无审批记录**（刷新后回放等无据场景）→ **跳过扣减**，不无据写 cart。

## 裁决③：实现形态

- `useCartStore` 只增不改：新增两 action——`alignWithOrderItems(items:
{productId, quantity}[])`（裁决①）/ `deductExecutedItems(items)`（裁决②）；
  依赖方向保持单向 assistant → cart；persist 机制零改动（items-only partialize
  自动跟随）。
- assistant store 两触点：`editOrder` 内调 align（确认点）；tool-output-available
  的 placeOrder 成功回执处分调 deduct（按 toolCallId 找回审批 items 后）。
- 无 UI 行为变更：不自动开 drawer、无角标、无提示文案（「已下单」角标展示属既有
  搁置可选项，本 G 明确不做）。
